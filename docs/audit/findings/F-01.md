## 1. Overview

## 4. Affected components

- `serializeCompactUser` (line 5546)
- `processIncomingCloudPacket` (line 5714)
- public ntfy topics and KV namespace constants (4298–4304)

## 5. Security boundary

A synchronization channel carrying user records must authenticate writers and avoid publishing identity data to anonymous readers. V4.8.0 added authorization for tombstone merges, but the channel itself is still public.

## 6. Root cause

Compact user records are broadcast to public channels. Password, seal and backend token were blanked in V4.8.0, but name, class, Gmail and status remain. The admin packet signature still uses a bundle-literal secret, so a 'validly signed' tombstone is not proof of admin authority.

## 7. Evidence

- `F-01-T12`, `F-01-T16`, `P4-19` and `IV-29` verify unsigned tombstones are rejected.
- `IV-32` observes a locally signed admin packet inserting an active VIP record with seal and signature.

## 11. Expected behavior

No student identity field should be visible to anonymous channel readers. Only a server-authorized writer should be able to tombstone or restore a record.

## 12. Actual behavior

Identity fields remain in the compact wire format. Unsigned tombstones are rejected, but a signature computed from the bundle literal is accepted and merges locally.

## 13. Impact

Student identity data may be exposed to anyone with channel read access. A party able to deliver a packet to a client can locally delete or restore records by reproducing the client-side signature. Live cross-client effects were not verified.

## 14. Attack scenario

An observer reads a public sync topic and collects names, classes and Gmail addresses. Separately, a local script delivers a signed tombstone to a target client, which removes the record from that client's view until the next authoritative sync.

## 15. Remediation

1. Remove identity fields from the public wire format and minimize snapshots to opaque IDs.
2. Put ntfy/KV behind an authenticated proxy with per-user read and write ACLs.
3. Replace the bundle-literal admin signature with a server-held key and mandatory nonce/sequence validation.
4. Rotate the cloud admin secret and retire the old public topics.
