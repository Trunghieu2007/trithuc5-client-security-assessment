# F-02: Admin authentication is delegated to a server session

**Severity:** Informational  
**CVSS v4.0:** not scored — see `../03-methodology.md`.  
**Confidence:** Confirmed  
**Status:** Fixed  
**Evidence state:** FIXED-V4.8.5 / VERIFIED-V4.8.6  
**Build pin:** V5.4.6, SHA-256 `2dbf781e4febf2e47a78da81352227de30c4972a8f0491e4864bdb32e370f61c`

## 1. Overview

This finding was verified against the source-hash-pinned V5.4.6 client build. Evidence comes from captured headers, static source review, or real extracted functions executed in an isolated Node VM with synthetic fixtures. No production state was modified.

## 2. Severity

**Assigned severity:** Informational. **CVSS vector/score:** not scored. Attack prerequisites, complexity, privileges, user interaction, scope and impact are stated qualitatively below rather than converted into an uncalculated numeric score.

- Attack prerequisites: local script execution on the app origin or access to the pinned public bundle; no server credentials.
- Attack complexity: low for the measured paths; the functions execute offline from bundle literals or local state.
- Required privileges: none in the tested client context.
- User interaction: the tester performs the action in their own browser; no victim interaction was tested.
- Scope: browser-local by default; cross-client effects are UNVERIFIED.
- Confidentiality / integrity / availability: see Impact below; no availability impact was measured.

## 3. Status

Confirmed — Fixed. Evidence state: FIXED-V4.8.5 / VERIFIED-V4.8.6.

## 4. Affected components

- `loginAdmin()` server call (31907-31959)
- server session restore (34604-34618)
- empty admin/vault hash literals (2052-2055)
- `computeAdminSessionSig` with `__TT50_EPH_ADM_SALT_V485__` (4166-4170)
- remembered-session restore (3740-3752)

## 5. Security boundary

Authentication and session issuance must be server-side. A browser cannot prove its own administrator identity.

## 6. Root cause

V4.8.0 compared bundle-literal hashes and minted a session from a bundle-literal salt. V4.8.5 removed the literals, made the salt ephemeral per window, cleared the remembered session at boot, and accepted a client session only when the /api/admin/login HttpOnly cookie flag is set.

## 7. Evidence

- `F-02-T01` shows a locally forged remembered session is cleared by the runtime integrity gate.
- `F-02-T05` confirms POST/GET/DELETE /api/admin/login and the absence of the old salt and hash literals.
- `P4-11` confirms the per-window salt makes offline signature replay non-reproducible.
- `IV-20` confirms the same independent result.

All evidence files are sanitized and indexed in `../evidence/README.md`. No real credential, real user record or production packet body is stored.

## 8. Reproduction prerequisites

- Pinned V5.4.6 source.
- No real admin credential is used or stored in this report.

## 9. Reproduction steps

1. Write a synthetic remembered admin session with a signature computed in the same VM.
2. Invoke the extracted restore block and observe the transient login state.
3. Run the runtime integrity gate without the server-verified flag and observe logout.
4. Confirm the source contains the server API, empty hash literals and ephemeral salt.

## 11. Expected behavior

Admin login must require a server-authenticated credential and a server-issued session that the client cannot mint.

## 12. Actual behavior

The locally forged session does not survive the runtime gate; admin login requires the server API, and the old bundle salt and password hash are absent.

## 13. Impact

The old offline admin impersonation path is removed. A residual local field write (`saveAdminCredentials`) still stores a client-computed hash in localStorage, but it no longer authenticates to the server.

## 14. Attack scenario

A user writes a forged session to localStorage and reloads; the app removes it and presents the anonymous state because no server-verified flag exists.

## 15. Remediation

1. Keep `F-02-T01/T05`, `P4-11` and `IV-20` as regression assertions.
2. Remove or server-synchronize the obsolete client-side `saveAdminCredentials()` hash write.
3. Add server-side rate limiting, CSRF protection and audit logging to /api/admin/login.
