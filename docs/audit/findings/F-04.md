# F-04: Exam answers were recoverable from a bundle-seeded client vault — FIXED

**Severity:** Low  
**CVSS v4.0:** not scored — see `../03-methodology.md`.  
**Confidence:** Confirmed  
**Status:** Fixed  
**Evidence state:** FIXED-V5.4.2 / VERIFIED-V5.4.6  
**Build pin:** V5.4.6, SHA-256 `2dbf781e4febf2e47a78da81352227de30c4972a8f0491e4864bdb32e370f61c`

## 1. Overview

This finding was verified against the source-hash-pinned V5.4.6 client build. Evidence comes from captured headers, static source review, or real extracted functions executed in an isolated Node VM with synthetic fixtures. No production state was modified.

## 2. Severity

**Assigned severity:** Low. **CVSS vector/score:** not scored. Attack prerequisites, complexity, privileges, user interaction, scope and impact are stated qualitatively below rather than converted into an uncalculated numeric score.

- Attack prerequisites: local script execution on the app origin or access to the pinned public bundle; no server credentials.
- Attack complexity: low for the measured paths; the functions execute offline from bundle literals or local state.
- Required privileges: none in the tested client context.
- User interaction: the tester performs the action in their own browser; no victim interaction was tested.
- Scope: browser-local by default; cross-client effects are UNVERIFIED.
- Confidentiality / integrity / availability: see Impact below; no availability impact was measured.

## 3. Status

Confirmed — Fixed. Evidence state: FIXED-V5.4.2 / VERIFIED-V5.4.6.

## 4. Affected components

- gzip/XOR exam vault `var __ENC_GZ` (now 191 answerless exam shells)
- `ensureExamHydratedFromServerV533` (line 3940)
- `submitExamToServerPhase2V530` (line 4025)
- `/api/exams/fetch` and `/api/exams/submit`

## 5. Security boundary

Answer keys and grading belong on a server if exam results have any consequence.

## 6. Root cause

V5.4.2/V5.4.3 moved questions to `/api/exams/fetch` and grading to `POST /api/exams/submit`. The shipped vault now contains 191 exam shells with zero answers and zero questions; every record carries `_serverGradedV530` and `_serverExamV533`.

## 7. Evidence

- `F-04-T01` decodes the current vault and reports 191 exams / 0 answers / 0 questions.
- `F-04-T03` confirms the server grading endpoint is called.
- `poc_f04_exam_answers.js` is read-only and validated by `poc-suite-validation.txt`.

All evidence files are sanitized and indexed in `../evidence/README.md`. No real credential, real user record or production packet body is stored.

## 8. Reproduction prerequisites

- Pinned V5.4.6 source.
- Local Node decoder; no live exam attempt.

## 9. Reproduction steps

1. Locate the embedded compressed chunks and seed values.
2. Reconstruct the vault offline with the bundle's own algorithm.
3. Count exams and answer entries; confirm both are zero.

## 11. Expected behavior

Answer keys should not be present in client-downloadable artifacts; grading should occur server-side.

## 12. Actual behavior

The shipped bundle contains no answer keys or questions; grading is performed by the Vercel API.

## 13. Impact

The previous offline answer extraction and client-authoritative score path are removed. The score returned by the server is applied to the local record.

## 14. Attack scenario

A user copies the bundle, runs the documented decoder, and extracts the answer key without starting an exam.

## 15. Remediation

1. Keep answer keys and questions server-only; retain `F-04-T01` as a regression.
2. Keep `/api/exams/submit` authoritative and avoid trusting pre-server local `calc.total`.
3. Retire any legacy answer-bearing bundle from distribution.
