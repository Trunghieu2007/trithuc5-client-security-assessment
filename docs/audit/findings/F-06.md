# F-06: Anti-cheat controls are UX-only

**Severity:** Low  
**CVSS v4.0:** not scored — see `../03-methodology.md`.  
**Confidence:** Confirmed  
**Status:** Open  
**Evidence state:** LOCAL_CONFIRMED (user-tested userscript in earlier phase)  
**Build pin:** V5.4.6, SHA-256 `2dbf781e4febf2e47a78da81352227de30c4972a8f0491e4864bdb32e370f61c`

## 1. Overview

This finding was verified against the source-hash-pinned V5.4.6 client build. Evidence comes from captured headers, static source review, or real extracted functions executed in an isolated Node VM with synthetic fixtures. No production state was modified.

## 2. Severity

**Assigned severity:** Low. **CVSS vector/score:** not scored. Attack prerequisites, complexity, privileges, user interaction, scope and impact are stated qualitatively below rather than converted into an uncalculated numeric score.

- Attack prerequisites: local script execution on the app origin or access to the pinned public bundle; no server credentials.
- Attack complexity: low for the measured paths; the functions execute offline from bundle literals or local state.
- Required privileges: none in the tested client context.
- User interaction: the tester performs the action in their own browser; no victim interaction was tested.
- Scope: browser-local by default; cross-client effects are UNVERIFIED.
- Confidentiality / integrity / availability: see Impact below; no availability impact was measured.

## 3. Status

Confirmed — Open. Evidence state: LOCAL_CONFIRMED (user-tested userscript in earlier phase).

## 4. Affected components

- `preventDefault`-based event suppression
- DOM overlays, CSS blur, watermark
- closure-local handlers

## 5. Security boundary

UI obstruction is not an integrity control. Exam integrity must be enforced by the server.

## 6. Root cause

Handlers are registered in closure scope and rely on default browser behavior. Blocking listener registration at document-start prevents them from being attached.

## 7. Evidence

- `poc-suite-validation.txt` executes the console neutraliser and userscript variant safely.
- Earlier-phase user test confirmed the userscript variant in a real browser without touching production data.

All evidence files are sanitized and indexed in `../evidence/README.md`. No real credential, real user record or production packet body is stored.

## 8. Reproduction prerequisites

- Own browser, test page, synthetic exam state.
- No real exam or grade involved.

## 9. Reproduction steps

1. Apply the document-start neutraliser before app scripts register handlers.
2. Observe that blur/overlay and copy-block handlers do not engage.
3. Stop the neutraliser with the documented function.

## 11. Expected behavior

Exam restrictions should be server-enforced and not depend on client event handlers.

## 12. Actual behavior

Client-side anti-cheat can be neutralised locally while the app still renders content.

## 13. Impact

The controls deter casual copying but do not protect exam integrity.

## 14. Attack scenario

A user injects a small userscript that blocks listener registration; restriction overlays no longer appear.

## 15. Remediation

1. Relabel anti-cheat as UX guidance rather than a security control.
2. Enforce time limits, attempt counts and grading server-side.
3. Keep cosmetic watermarks for deterrence only.
